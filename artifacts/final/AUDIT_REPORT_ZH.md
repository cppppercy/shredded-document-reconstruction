# 综合审核与整改记录

## 已确认问题与处理

| 类别 | 审核结论 | 本次处理 |
| --- | --- | --- |
| 页面性能 | `st.tabs` 的未选中分析页也会执行；演示图片每次重读/缩放 | 改为互斥页面单选，只渲染当前页；缓存演示原图、缩略图、上传解码与研究结果 |
| 模型加载 | 首次点击重建可能训练模型 | 生成并加载固定交互模型文件；保留无模型文件时的可复现训练回退 |
| 分析口径 | 原页面强调历史开发配置，且混入不同批次 | 研究页只读取新增最终独立集的逐案例结果；历史消融移入附录 |
| 组合样本量 | 容易把小格子的波动当作结论 | 页面显示每格样本数；类型×条件每格仅 6 例时明确提示不稳定 |
| 案例追溯 | 历史 JSON 保存的是原始位置顺序，不能直接用于图像重放 | 重新按固定训练/输入运行四个已保存案例，并逐项核对保存指标后生成案例图 |
| 算法 | 学习方法并非稳定超过规则方法 | 未在最终集后调参；保留负结果，记录其条件性优势与失败场景 |
| 全局优化 | 评估了 Python/NumPy 改写尝试 | 试验版本在 12 条人工矩阵上约 0.307 秒且更慢，已撤销；保留已验证的 Held–Karp 实现 |

## 尚未解决或不能夸大的事项

- 外部公开页面仍是完整页的模拟切条，不是物理碎纸扫描。
- 首次重建约 2 秒，因为两种方法都真正执行局部特征和全局动态规划；没有用预先计算的答案替代。
- 浏览器自动化已用于真实截图和交互，但性能表的精确数字是服务端 Streamlit 重跑时间，不等同于浏览器绘制时间。
- 组合格子只有 6 个独立页面，不能用于强适用性结论。
